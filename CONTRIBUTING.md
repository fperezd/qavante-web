# Contributing — qavante-web

Convenciones obligatorias para contribuir al repo. Leelas antes de abrir tu primer PR.

> Este doc es un **deliverable de C0-18** y consolida convenciones dispersas en [CLAUDE.md](./CLAUDE.md), [QAVANTE_SPRINT_C0_KIT.md](./QAVANTE_SPRINT_C0_KIT.md) y [docs/adr/](./docs/adr/). Si encontrás contradicción, gana el ADR si existe; si no, **abrí un issue** antes de actuar.

## Setup local

Ver [README.md § Setup local](./README.md#setup-local).

## Branches

Una rama por ticket atómico (C0-NN o issue de GitHub). Naming:

```
<tipo>/<scope>-<slug-corto>
```

Donde `<tipo>` es `feat | fix | chore | docs | test | refactor` (alineado a Conventional Commits).

Ejemplos vivos en `git log`:

```
feat/c0-prod-smoke-test
docs/c0-adr-system
docs/c0-iac-ops-docs
fix/c0-13-middleware-src
docs/master-doc-v2.6.4-qavante-com
```

**No hay rama `develop`**. PR `<tipo>/c0-...` → `main` con **squash merge**. Justificación en Kit Sprint C0 sec 2.1.

## Commits

[Conventional Commits](https://www.conventionalcommits.org/) con scope `c0` (o `c0-NN`):

```
feat(c0): init Next.js 15 skeleton with App Router
fix(c0-13): handle 401 redirect in API client
chore(c0): bump shadcn/ui to latest
test(c0): add e2e for login flow
docs(c0): update README with setup instructions
```

Cada commit y PR llevan la firma:

```
Generated by CC-WEB.
```

(Si la edición es 100% humana, se omite la firma. Por convención, esto es raro en este repo porque Claude Code agentic flows son la norma.)

## Pull Requests

**Tamaño objetivo:** <300 líneas modificadas (excluyendo tests y archivos generados como `src/lib/api/types.ts`). PRs más grandes requieren justificación en el body.

**Cada PR cierra UN solo issue** con `Closes #N` en el body. Si tu cambio toca múltiples issues, dividilo en múltiples PRs.

**Template:** [.github/pull_request_template.md](./.github/pull_request_template.md) — completar todas las casillas aplicables.

**CI obligatoria:** lint, typecheck, test (vitest), build (Next.js), e2e (Playwright), secrets-scan (gitleaks), smoke post-deploy contra prod. Si rojo, **no se mergea**.

**Reviewer obligatorio:** Fernando (CODEOWNER). No hay self-merge.

## Definition of Done (por PR)

Adicional a la CI verde, validar mental o explícitamente:

- [ ] **Sin `export const runtime = 'edge'`** en pages/routes/middleware (incompatible con `@opennextjs/cloudflare` — ver [ADR-0001](./docs/adr/0001-cloudflare-workers-vs-pages.md)).
- [ ] **Sin Node-only APIs** no soportadas por `nodejs_compat` (`child_process`, `fs` nativo en flow de runtime, etc.). Listado: [developers.cloudflare.com/workers/runtime-apis/nodejs](https://developers.cloudflare.com/workers/runtime-apis/nodejs/).
- [ ] **Sin `any`** sin justificación inline (`// eslint-disable-next-line @typescript-eslint/no-explicit-any -- razón`).
- [ ] **Sin Storage APIs** para tokens — `localStorage`, `sessionStorage`, `IndexedDB` están prohibidos. Solo cookies httpOnly. Ver CLAUDE.md regla 6.
- [ ] **Sin secrets en código** — validado por gitleaks pero también revisar `.env*` accidentales.
- [ ] **Tests pasando** localmente antes de pushear (`npm run test && npm run e2e`).
- [ ] **Lighthouse mobile ≥85** en `/login` y ≥90 en `/app/inicio` si la PR las toca (verificar manual con devtools hasta que `lhci` esté en CI).
- [ ] **Documentación actualizada** — si cambiás API pública, contratos cross-repo, decisiones arquitecturales: PR del doc en el mismo PR del cambio.

## Decisiones arquitecturales

Si tu PR introduce un cambio arquitectural (stack, infra, contratos cross-repo, convenciones), **abrí un ADR** primero o en el mismo PR. Ver [docs/adr/](./docs/adr/) — formato Michael Nygard, template en [docs/adr/template.md](./docs/adr/template.md).

Regla dura: **si un ADR existente contradice tu instinto, gana el ADR.** Si pensás que el ADR está mal, abrí un nuevo ADR que lo supersede con tu propuesta, no actues silenciosamente.

## Cross-repo (`qavante-api` backend)

- Si necesitás un endpoint que no existe en backend: **abrí issue en `qavante-api`** con shape esperado + permisos + ejemplo de request/response. **No** lo pidas directamente al agente de backend.
- Si un endpoint nuevo en backend afecta el frontend: ANTES de implementar, correr `npm run generate:api` para regenerar `src/lib/api/types.ts`. Verificar contra `https://api.qavante.com/openapi.json` (o `tooxs-gestion-api.fly.dev` hasta que la migración del ADR-0003 esté completa).
- Contratos vivos en [docs/backend-contracts/](./docs/backend-contracts/) — actualizar en el mismo PR que el cambio cross-repo.

## Reglas duras (no negociables)

Resumen del prompt CC-WEB ([CLAUDE.md](./CLAUDE.md)). Si dudás, leer el original:

1. Trabajás **solo** en `qavante-web`. No tocás otros repos.
2. **No modificás** el Documento Maestro ni `src/lib/api/types.ts` (generado) sin protocolo explícito.
3. **No force-push** a main ni ramas compartidas.
4. **No mergeás sin aprobación** humana.
5. **No anticipás Fase 2** (OAuth Google/MS, app móvil, multi-tenant en prod, etc.).
6. **Regla de no-regresión** (CLAUDE.md): no rompés código que ya funciona. Si tocás un archivo deployado, validás contratos públicos y corrés tests antes y después.

## Reportar problemas

- **Bugs** en este repo: GitHub issues con label `bug` + reproducción mínima.
- **Decisiones arquitecturales** a discutir: abrir issue + draft ADR en `docs/adr/` con status `Proposed`.
- **Bugs en producción de `app.qavante.com`** detectados por usuario: capturar en issue + ver si el smoke test ([tests/e2e/prod-health.smoke.spec.ts](./tests/e2e/prod-health.smoke.spec.ts)) puede atajarlo a futuro.
